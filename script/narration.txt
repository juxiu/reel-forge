# CHAPTER 1 什么是 Agent

「Agent」这个词 | 在不同人嘴里指的东西并不一样 | 同一个词有几种定义 | 先分清它

有人说的 agent | 是完全自主的系统 | 长期独立运行 | 用各种工具完成复杂任务

也有人用同一个词 | 指按预定流程走的 | 更程式化的实现

Anthropic 把这些变体 | 统一叫 agentic systems | 但划了一条 | 重要的架构分界线

分界线的一侧是 workflow | LLM 和工具 | 由预定义代码路径编排

# CHAPTER 2 分界线的两侧

另一侧才是严格的 agent | 系统自主决定步骤 | 长时间独立运行 | 用工具完成任务

过去一年 | Anthropic 与数十个团队 | 一起构建 LLM agent

结论反复出现 | 最成功的实现 | 既不用复杂框架 | 也不用专用库

他们用的是 | 简单、可组合的模式 | 事实证明，简单模式反而更好用

与其为每个场景 | 各造一个定制 agent | 不如用可组合的能力 | 去完成专门化

写死的路径负责可控 | 交给模型的负责灵活 | 先想清楚 | 你的任务要哪一种

# CHAPTER 3 从通用到专业

但通用能力不等于能干活 | 真实工作需要 | 程序性知识和组织上下文

模型能力在提升 | 通用 agent 已经能 | 和完整的计算环境交互

比如 Claude Code | 靠本地代码执行和文件系统 | 跨领域完成复杂任务

agent 越强大 | 就越需要可组合、可扩展 | 可移植的方式 | 来装上领域专长

答案是 Agent Skills | 指令、脚本和资料 | 组织成文件夹 | agent 按需发现并动态加载

专长不再散落在提示词里 | 而是被打包成 | 可组合的资源

# CHAPTER 4 技能的形状

一个技能就是一个目录 | 一份 SKILL.md | 加上指令、脚本和资源

给 agent 写技能 | 就像给新员工 | 准备一份入职指南 | 照着做就能上手

把你的专长打包进去 | 通用 agent | 就变成贴合需求的 | 专用 agent

任何人都能 | 捕获并分享程序性知识 | 来专门化自己的 agent | 而不是每个用例重造一个

这套东西已发布为 | 开放标准 | 能力可以跨平台移植 | 不被私有绑定锁死

回到开头的问题 | agent 是什么 | 它是一条谱系 | 从写死的流程 | 到自主的系统

框架会过时，模式不会 | 把专长装进 | 可组合的容器 | agent 才能真正干活
